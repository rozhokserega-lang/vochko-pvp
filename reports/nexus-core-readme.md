# Как проверить Ядро Нексуса

Ветка: `feature/nexus-core`, рабочая копия `D:/Rotogochi/vochko-pvp-nexus-core`.

```powershell
rtk npm test
rtk npm run test:core
rtk npm run test:local
rtk npm run build
rtk proxy node scripts/dev-local.mjs 5190
```

Открыть `http://127.0.0.1:5190/`, выбрать бота либо создать комнату и открыть её во втором профиле браузера.
Все API этого локального стенда выполняются в памяти с настоящими обработчиками хода/подготовки/состояния.
Внешние запросы к Supabase не используются. При перезапуске сервера временные комнаты исчезают.

1. Разместить 12 из 13 карт по шести парам любых мастей.
2. После ответа сервера Ядро открывается. Можно открыть «Усиления Ядра» и посмотреть потенциальные/размещённые способности.
3. Перетащить последнюю карту в Ядро; на телефоне нажать карту и затем Ядро.
4. После подтверждения карта исчезает из руки. Выбор неизменяемый, кнопка «Готово» становится доступной.
5. Сервер ждёт второго человека, либо выбирает ход бота автоматически.
6. В бою видны оба индикатора Ядра; в следующем раунде бонус сброшен, сожжённая карта отсутствует в новой руке.
7. Перезагрузка между стадиями восстанавливает серверную подготовку.

Старый режим доступен через `createRoom({nexusCoreEnabled:false})`: 14 случайных карт, без обязательного Ядра.

## Повторить эксперименты

```powershell
rtk proxy node scripts/nexus-core-design.mjs
rtk proxy node scripts/nexus-core-balance.mjs --games 1000 --policy-games 1000 --workers 8
rtk proxy node scripts/nexus-core-balance-report.mjs
```

Это перезаписывает `nexus-core-simulations-final`; для отдельной серии указать другой `--out`.
Для отчёта используется только завершённая финальная серия с совпадающим SHA-256 источников.
Ранние smoke/пилотные/отбракованные серии не включены в финальные 5000 матчей.

## Результаты и ограничения

- `nexus-core-ability-design.md`: таблица 20 способностей × 4 тира, лимиты и профили B/C.
- `nexus-core-architecture.md`: приватное состояние, API, фазы, совместимость и выпуск.
- `nexus-core-balance.md`: результаты 5000 матчей и доверительные интервалы.
- `nexus-core-screenshots`: ПК/телефон, предпросмотр, поглощение, итог и бой.
- `nexus-core-verification`: журнал тестов и итог проверок.

Профиль C выбран как более осторожный набор коэффициентов, а не доказанный глобальный оптимум. Партии заметно длиннее режима A. Превосходство адаптивного выбора над эвристикой младшей карты статистически не подтверждено; безусловное сжигание старшей карты оказалось существенно хуже. Политики с равными рангами используют фиксированный порядок руки, не перебирают отдельную оптимальную стратегию каждого игрока.

Замеры времени основного турнира выполнены восемью потоками с общим для конфигураций кэшем DP: разницу времени B/C нельзя приписывать только балансу. Серверный лимит AI мягкий; hosted Supabase и нативный Deno в этом цикле не запускались. Проверены реальные тела обработчиков с внедрённым SQL и браузеры с локальным HTTP-стендом.

Production не публиковался. Для выпуска нужны согласованные версии клиента и серверных функций; нельзя выложить только клиент. Уже созданные матчи без флага продолжают использовать 14 карт и не требуют Ядра. На `main` эта ветка не сливалась.
