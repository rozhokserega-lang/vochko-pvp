# Ядро Нексуса XP v2

База: `c495db370c5e351bd7492ad69af606fdac4d3e13`, ветка `feature/nexus-core-xp`.

## Этап 1 — аудит

Текущая игра уже использует 13 карт и индивидуальную колоду 52 карты (`shared/player-deck.js`). Двенадцать карт образуют три атакующие и три защитные пары; последняя сгорает. `shared/validation.js` проверяет принадлежность и уникальность карт. Порядок расхода карт не менялся.

Состояние — приватный JSON матча. Подготовка и разрешение хода сериализованы существующей транзакцией с блокировкой строки матча. Персональные DTO формирует `get-state`. Основной расчёт, включая бота, выполняет `shared/engine.js`.

Затронуты: `shared/core-progression.js`, `engine.js`, `abilities.js`, `core-bot.js`; Edge Functions `create-room`, `rematch`, `prepare-core`, `submit-turn`, `get-state`; клиент `src/main.js`, `NexusCorePanel`, предпросмотр атаки и HP Нексуса; справочник и калькулятор. Геометрия арены и правила комбинаций не переделывались.

## Этап 2 — механика

- 2–10 = номинал XP; J/Q/K/A = 11/12/13/14, независимо от масти.
- XP до 100. Уровень и бонусы вычисляются из XP: 20 → +5 HP; 40 → +1 атаки пары; 60 → +3 щита Нексуса; 80 → ещё +1 атаки; 100 → ещё +10 HP.
- HP растёт на разницу максимумов; мёртвый Нексус не воскресает. Лечение ограничено актуальным максимумом 80/85/95.
- Бонус атаки прибавляется один раз к силе пары после ослабления атаки, до защиты и её уникальных эффектов.
- XP начисляет `prepare-core` после проверки карт; номер раунда исключает повтор при resolve, повторном запросе и восстановлении страницы.
- Чужие XP, уровень, подготовка и карта Ядра не включаются в DTO/публичный отчёт. Фактические HP/щит публичны. Бот не получает приватный прогресс и список жертв соперника.
- Новые матчи и реванши используют `coreVersion:2`; старые активные матчи сохраняют v1.

### Выбранная интерпретация постоянного щита

В исходной реализации были щит пары и процент урона Нексусу по числу прорывов `[0,40,70,100]`, но не постоянный запас щита. Добавлен минимальный совместимый вариант: +3 поглощает до 3 единиц **каждого попадания в Нексус**, после защиты пары и до процентного коэффициента. Например, остаток 10 при 40%: round((10−3)×0.4)=3 HP. Общие функции урона применяют это также к горению/вторичным попаданиям. Башни бонуса не получают. Это поведение необходимо оценить при игровом просмотре перед релизом.

## Этап 3 — проверка

`npm test`: **389/389**, включая 13 новых тестов.

Покрыты номиналы всех 52 карт, пороги, кап, несколько уровней за начисление, невоскрешение, лечение, щит/процентные ограничения, бонус атаки один раз, конкурентные запросы, запрет поддельных XP/карты, PvP, бот, восстановление DTO, расход колоды, сброс нового матча и скрытие чужого Ядра.

Серверные тесты выполняют реальные обработчики через существующий in-memory SQL adapter. Дополнительно проверен HTTP-сценарий локального сервера: создание матча, подготовка, отклонение карты, поглощение, восстановление, бой с ботом, запрос каждого PNG. Это не проверка размещённых Supabase Functions, PostgreSQL под нагрузкой или реального Realtime.

`npm run build`: успешно; существующее предупреждение о крупных чанках остаётся.

## Этапы 4–5 — панель

`NexusCorePanel.js` / `nexus-core-panel.css`: одна личная панель, открываемая нажатием на маленькое Ядро под HP своего Нексуса, отдельные PNG-слои, SVG-кольцо пяти этапов, XP, уровень, пять строк, блокировки/галочки, вспышка/разблокировка после ответа сервера. На всех экранах маленькое Ядро принимает последнюю карту перетаскиванием; нажатие открывает панель. Используются прежние изображения закрытого/открытого Ядра и анимация ожидания. Кнопка — отдельный элемент в потоке после HP, без увеличения масштаба в закрытой фазе. Постоянная левая колонка убрана по уточнению пользователя. Существующие Pointer Events сохраняются.

`public/assets/nexus-core/`: 13 слоёв из предоставленных PNG, без генерации новой графики. `manifest.json` фиксирует исходники, SHA256 и нарезку; `scripts/prepare-xp-core-assets.py` воспроизводит подготовку. У листа иконок была запечённая шахматка: удалён связанный светлый фон. Тест проверяет декодирование и настоящую прозрачность всех 13 слоёв.

Положение/масштаб графических слоёв настраиваются CSS-переменными. Динамические значения и текст не запечены в PNG. Предпросмотр атаки учитывает бонус; ключ сохранения индикатора содержит бонус, чтобы старое число не оставалось после повышения уровня.

## Этап 6 — не завершён

`npm run test:xp-ui` подготовлен для 1920×1080, 2560×1440, 1366×768 и 390×844: геометрия, перетаскивание, отказ/повтор, XP, F5 и бот. В текущей ограниченной среде Chrome завершается при запуске (`SIGABRT`, затем `kill EPERM`) до загрузки страницы. Поэтому скриншоты, размеры, сенсорный drag и анимации **не подтверждены визуально**. Их необходимо проверить на обычном запуске на Маке/телефоне.

## Перед публикацией

1. `npm ci && npm test && npm run build`.
2. `npm run test:xp-ui` и ручной просмотр на телефоне; оценить постоянный щит.
3. Согласованно опубликовать серверные обработчики `create-room`, `rematch`, `prepare-core`, `submit-turn`, `get-state` вместе с их shared-зависимостями, затем клиент. SQL-миграция не требуется.

`main` и production не изменялись.
