# Проверка сетевого релиза — 13 ноября 2026

Проверены текущий клиент и настоящий Supabase проекта `vo4ko`. Полный браузерный матч выполнен с локально собранным клиентом и боевыми Auth, Edge Functions, Postgres и Realtime, без подмены обработчиков или изменения HP для ускорения игры. Использованы две независимые анонимные сессии. Проверка с реальным вторым человеком не проводилась.

## Результат

- 368 автоматических тестов прошли; сборка, локальный PvP/PvE и браузерный сценарий Ядра прошли.
- Полный сетевой матч с легальной атакующей расстановкой завершился на 6-м раунде: Нексусы 0/23. Оба клиента показали результат и перешли в один реванш. [Машинный журнал](network/live-match.json).
- Подтверждены вход по ссылке, приватность текущих карт/подготовки, постоянное сжигание карт, переподключение после F5, offline/online, повторное подтверждение хода, повторный запрос реванша и F5 после реванша.
- Четыре одновременных запроса подтверждения от двух игроков разрешили раунд ровно один раз, с одним сжиганием для каждого игрока. Старый клиент без флага Ядра получил 14 карт. [Журнал конкурентных запросов](network/concurrency.json).

## Исправления

1. Сервер отправляет только `{matchId, version, eventType}` через HTTP Broadcast с ограничением ожидания 2,5 секунды. Сбой уведомления не превращает уже сохранённый ход в ошибку HTTP.
2. Клиент дополнительно сверяет состояние раз в 5 секунд, после восстановления Realtime, возврата сети и фокуса. Неизменившаяся версия не перерисовывает руку и не сбрасывает выбор карт.
3. Повторный вход участника в занятую комнату возвращает его прежнее место. F5 с текущей ссылкой восстанавливает сохранённый матч; ссылка после реванша обновляется на новую комнату.
4. Создание реванша идемпотентно под блокировкой матча. Повторные запросы возвращают один `nextMatchId`.
5. Новый клиент явно передаёт `nexusCoreEnabled:true`; старые клиенты сохраняют прежний протокол раздачи.
6. GitHub Pages проверяет тесты перед сборкой на Node 24.

## Сервер и публикация

Обновлены все семь функций: `create-room`, `join-room`, `get-state`, `prepare-core`, `submit-turn`, `rematch`, `leave-room`. Перед обновлением сохранены локальные копии шести ранее развёрнутых функций. Новых SQL-миграций не требуется. JWT проверяется внутри каждой функции через `auth.getUser` и проверку участия в матче.

Пуш в `main` публикует клиент через GitHub Actions. Серверные функции развёрнуты отдельно до публикации клиента; один пуш в GitHub сам по себе их не обновляет.

## Повторение

`npm test`, `npm run build`, `npm run test:local`, `npm run test:core`.

Для настоящего backend: задать `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, выполнить `npm run test:network:live -- --attack-heavy`. Команда создаёт реальные тестовые сессии и комнаты. Для проверки уже опубликованного сайта дополнительно задать `LIVE_FRONTEND_URL=https://rozhokserega-lang.github.io/vochko-pvp/` и передать `--smoke`; без этого параметра запускается полный матч.

Схема уведомлений сверена с [документацией Supabase Broadcast](https://supabase.com/docs/guides/realtime/broadcast) и [статусами подключения](https://supabase.com/docs/reference/javascript/subscribe). Автоматические проверки не гарантируют доступность интернета или облачных сервисов в каждый момент времени.
