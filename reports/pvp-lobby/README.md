# Комната ожидания PvP

Ветка: `feature/pvp-lobby-redesign`, основана на `main` (`dc1bf02`). Новая версия не объединена с main и не развёрнута в production.

## Что реализовано

Использованы все семь изображений пользователя: фоновая сцена, логотип, центральная панель, синяя и красная рамки игроков, VS и кнопка. Отсутствующих ресурсов нет. Исходные имена, размеры и SHA-256 записаны в [манифесте ресурсов](../../src/ui/waiting-room/assets/manifest.json). WebP занимает суммарно 1,14 МБ, прозрачность сохранена.

Красная рамка отражена через CSS `scaleX(-1)` только на изображении. Аватар расположен справа, текст читается в обычном направлении. HTML-подписи и состояния располагаются поверх графики. У центральной панели используется `border-image`, у рамок игроков — пропорциональные изображения.

Показаны настоящие ссылка, код и UUID комнаты. У всех трёх значений независимые кнопки копирования с подтверждением или сообщением об ошибке. Данные о балансе и раздаче берутся из `view.rules`: Ядро и 13 карт показываются только при включённой механике. Имена игроков сервер не передаёт, поэтому используются подписи «Ты», «Соперник» и роль участника.

Есть ожидание, подключение соперника, короткий переход VS, потеря соединения и повтор запроса. При сокращении анимации в настройках ОС переход происходит сразу. Рамки при свечении не двигаются и не масштабируются. Игровые механики, AI, колоды и правила начала боя не изменялись.

Отмена пустой комнаты теперь ожидает подтверждения API. При ошибке пользователь остаётся в комнате и может повторить отмену. Минимальное изменение `leave-room` закрывает комнату со статусом `waiting`; выход из уже начатого матча сохраняет прежний режим переподключения. Это исправление требует обновления этой функции при будущей публикации ветки.

## Проверки

- `npm test`: 371 тест прошёл.
- `npm run build`: сборка прошла.
- `npm run test:waiting`: создание, все кнопки копирования, клавиатура, зеркальная рамка, размеры 320/390/768/1366/1670, отсутствие горизонтальной прокрутки, offline/online, серверная ошибка и повтор, reduced motion, вход по ссылке и коду, подключение обоих игроков, автоматический старт, F5, отмена с ошибкой и повтором, закрытая и несуществующая комната. [Результат](browser-checks.json).
- `npm run test:local`, `npm run test:core`: прежние сценарии PvP/PvE и Ядра прошли.
- Две отдельные сессии через боевые Supabase Auth/Realtime/Edge/Postgres вошли через новый экран и провели один PvP-раунд, включая offline/online и повтор подтверждения. Получены реальные Realtime-сообщения на обоих клиентах. Клиент работал локально, серверные функции при этой проверке не обновлялись. [Журнал](live-smoke.json). Новая отмена проверена на локальном HTTP-сервере с реальным обработчиком функции, поскольку production deploy в этой задаче не выполнялся.

## Изменённые файлы

- `src/ui/waiting-room/WaitingRoom.js`, `roomRules.js`, `waiting-room.css`, `assets/*` — новый экран и предоставленная графика.
- `src/ui/Lobby.js` — совместимый экспорт `waitingRoom`.
- `src/main.js` — подключение DTO, состояния связи, переход к бою, надёжная отмена и закрытая комната.
- `src/lib/realtime.js` — необязательный callback состояния связи; прежний интерфейс подписки сохранён.
- `supabase/functions/leave-room/index.ts` — закрытие отменённой пустой комнаты.
- `scripts/dev-local.mjs`, `tests/server-fixture.mjs` — проверка отмены настоящим обработчиком и паритет локального сценария.
- `scripts/prepare-lobby-assets.mjs` — воспроизводимая подготовка предоставленных изображений.
- `tests/waiting-room.test.js`, `tests/browser-waiting-room.mjs`, `package.json` — проверки и команда `test:waiting`.
- `reports/pvp-lobby/*` — скриншоты и результаты.

## Локальный запуск

`npm run dev:local -- 5196`, затем открыть `http://127.0.0.1:5196/` и нажать «Создать комнату». Для второго игрока использовать другой браузер или отдельный профиль и перейти по ссылке комнаты.
