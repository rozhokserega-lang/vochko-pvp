## Что изменено

Любые масти можно объединять. На линии две пары, обе дают атаку и защиту. Каждая характеристика округляется после карточного множителя и затем после своего бонуса стихии; линия складывает уже округлённые характеристики. Все десять утверждённых коэффициентов находятся в `shared/elements.js` без повторения на клиенте/сервере.

Урон рассчитывается в обе стороны до определения победителя; оба Нексуса могут погибнуть одновременно. Укрепление и способности стихий отключены, включая накопленный поджог старого состояния. Сервер принимает только ID карт из своей руки, проверяет уникальность, три линии и шесть полных пар; поддельные числа/стихии/действия отклоняет. Имена `attack`/`defense` оставлены для двух слотов протокола. Сортировка линий выполняется по `lane`.

В интерфейсе осталась прежняя арена. Добавлена доступная с клавиатуры и телефона панель шести пар с суммами линий и раскрываемым расчётом. Старые места на башнях/Нексусах также принимают любые масти. Исправлена перестановка нанесённого/полученного урона в сводке. После боя раскрываются четыре использованные карты соперника на линии. Для лавы/вихря используются огненные ассеты, для льда водные, для грозы/песчаной бури старый ассет бури с временной цветовой обработкой.

## Результат аудита и сохранённые особенности

- HP соответствуют задаче: внешняя 12, внутренняя 18, Нексус 80. Лимит 45 раундов сохранён; по лимиту сравниваются HP Нексусов. Избыточный урон не переносится.
- В текущем коде каждая рука независимо выбирается из колоды 52 карт (7 красных + 7 чёрных), поэтому карты разных игроков могут совпадать. Это существующее отличие от одной общей раздачи, сохранено без изменения механики.
- Функция `shieldPct` фактически задаёт долю проходящего урона: 0/40/70/100% при 0/1/2/3 разрушенных внутренних башнях. Историческая подпись «Щит» сохранена.
- Линии обрабатываются в существующем порядке 0 → 1 → 2. Разрушение внутренней башни на ранней линии влияет на долю урона Нексусу на последующих линиях этого же раунда. Это прежнее правило сохранено; перестановка игроков A/B и порядка массива placements результат не меняет.
- Поля `fortify_lane`, `fortifyUsed`, `burn`, `fortified` оставлены для совместимости, но не дают эффектов. Уже сохранённое укрепление старого ожидающего хода игнорируется при разрешении.

## Ограничения и выпуск

SQL-адаптер проверяет настоящие обработчики, но не заменяет проверку реального Postgres, блокировок и доставки Supabase Realtime. Тестовый браузер получает локальные ответы этих обработчиков, broadcast имитируется. Удалённый PvP и deployment в этом сеансе не выполнялись. Нативный Deno type-check не запускался: Deno отсутствует. Серверный JS покрыт тестами; TS обработчиков исполняется через Node stripTypeScriptTypes (Node >=22.13, здесь 24.14.1).

Клиент и сервер нужно выпускать согласованно: старый сервер отклонит смешанные пары, старый клиент показывает прежние правила. После обновления Edge Functions и клиента рекомендуется начать новые матчи и обновить вкладки обоих игроков. GitHub workflow сейчас публикует только клиент — Edge Functions выпускаются отдельно согласно `docs/deployment.md`. Схема и SQL-миграции не меняются.

`tests/browser-v19.mjs`, `full-match.mjs`, `browser-final-round.mjs`, `verify-final-report.mjs` — исторические live-скрипты v19; часть ожиданий относится к старым правилам. Основной актуальный браузерный сценарий — `browser-elements.mjs`; исторический раннер оставлен как `test:browser:live` для последующей адаптации.

## Ручная проверка реального PvP после выпуска

1. Открыть обновлённый клиент в двух независимых браузерных профилях (один можно на телефоне). Создать комнату и войти по коду/ссылке.
2. Убедиться в раздаче 14 карт, по 7 каждого цвета. Выбрать ♥♠ для лавы, затем обратный порядок ♠♥; проверить одинаковую стихию. Аналогично проверить остальные девять сочетаний через несколько раздач.
3. Разместить по две пары на каждой линии, смешивая цвета в обоих слотах. Сверить названия, атаки/защиты, суммы линии и раскрываемый расчёт; повторная карта недоступна. Очистить пару нажатием без выбора и собрать снова. Проверить перетаскивание на прежние башни.
4. Отправить первый ход: сопернику не раскрываются карты. Отправить второй: у обоих один бой и общий расчёт, видны обе пары каждой стороны, две свободные карты в отчёте отсутствуют. Сверить HP и нанесённый/полученный урон с другого клиента.
5. Повторить на внутренних башнях и открытых этажах Нексуса. Сильный удар уничтожает только текущую цель; обе стороны могут получить урон. Укрепления/поджога нет.
6. Обновить вкладку между раундами, завершить матч, проверить финальный отчёт, ничью при обоюдной смерти и реванш. На телефоне повторить в обеих ориентациях: поле, расстановка и расчёт доступны прокруткой.
